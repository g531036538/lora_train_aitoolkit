# 迭代判读手册

> **这份文档只回答一件事**：第一批出图之后，看到什么现象，下一步该动哪个旋钮。
>
> 不回答：参数该怎么填（看 `docs/models/sdxl.md` / `krea2.md` / `moss_image.md` 的 ③ 起点参数）；
> 不回答：数据集怎么采集（只看 §9，八行）。
>
> **记号**：
> - `SRC` = 源码或官方文档里查到的事实，后面挂 `文件:行号` 或 URL（编号见 `docs/sources.md`）；
> - `COMMUNITY` = 社区报告，**未实测**，只当线索；
> - `UNVERIFIED` = 查不到，写明缺什么才能确认。
>
> 凡是没有 `SRC` 的数字（阈值、步数区间），都是**经验值，未实测**，不要当定论引用。

## 0. 怎么用

三步，顺序不要换：

1. **先排除非训练原因**（§2）。这一步能拦掉大约一半的「看起来像训练坏了」。
2. **对症状**（§3 主表 / §4 附带）。找到描述最接近的那一条。
3. **一次只改一个变量**（§1），改完看**停止条件**，到了就停。

速查表：

| 你看到的 | 先去 |
|---|---|
| 写了触发词，角色/概念根本不出现 | §2 触发词是否进了 caption → §3.2 |
| 每张都穿同一套衣服 / 背景总在同一个地方 | §3.1 |
| 同一个人，换角度就认不出 | §3.3 |
| 不写触发词，别的题材里也冒出这个角色 | §3.4 |
| 全身像还行，脸/手/小物件一放大就崩 | §3.5 |
| 整张图发灰、对比度塌、出现纯色块 | §2（VAE 精度 / 精度混用），**不要**先动训练参数 |
| 图里文字永远拼不对 | §4 |

---

## 1. 通用规矩

1. **一次只改一个变量**。同时改 lr 和 rank，结果变好你也不知道是哪个起的作用。
2. **用中间存盘比，不只比最后一版**。`save_every` 默认 1000（`toolkit/config_modules.py:25`），训练 2500 步就有 250/500/… 的中间档；过拟合拐点经常出现在 500–1500 之间，只看最后一版会误判成「学不会」。
3. **固定种子、固定提示词、固定采样参数**再比。采样参数不一致的对比没有意义。
4. **loss 曲线只能排除「没学到 / 炸了」，不能证明「学到了什么」**。loss 正常但图不对，是 caption 或数据的问题，不是训练没跑。
5. 先看「同一提示词换种子」是否稳定，再看「换提示词」是否还成立。前者查过拟合，后者查泛化。
6. 每次实验记一行（§8），否则三天后你自己也说不清哪版是哪个参数。

## 2. 先排除非训练原因

这一节的每一项，都能伪装成「训练坏了」。

| 现象 | 先查什么 | 依据 |
|---|---|---|
| 触发词完全没效果 | 触发词是否真的写进了每张图的 caption；SDXL 的 caption 超 **77 token 会被静默截断**，触发词在最前面也可能被别的词挤掉 | `SRC` `toolkit/train_tools.py:402-422`（`max_length=tokenizer.model_max_length`、`truncate=True`）；Krea2 上限 512（`krea2/src/text_encoder.py:45`）、MOSS 4096（`moss_image.py:70`） |
| 同上 | `trigger_word` 是否写在 `config.process` 层或 dataset 层；写错位置不会报错，只是不注入 | `SRC` `jobs/process/BaseSDTrainProcess.py:135,168-169`、`toolkit/dataloader_mixins.py:2367` |
| 整图发灰、对比度塌、出现纯色斑块 | VAE 精度：SDXL VAE 在 fp16 下不稳定，需 `vae_dtype: float32`（kohya 对应 `--no_half_vae`）；MOSS 官方加载即 `{"vae": float32}` | `SRC` kohya `docs/sdxl_train_network.md`、MOSS `USERGUIDE`；ai-toolkit 不会替你改精度（`stable_diffusion_model.py:447`） |
| 同上 | 训练精度与采样精度不一致（`train.dtype` bf16 但采样 fp16）、或 `standardize_images` 打开后色调被归一 | `SRC` `toolkit/config_modules.py:401,509` |
| 采样看起来「太强/太弱」 | CFG 口径：Krea2 的 yaml `guidance_scale` 会被减 1 再传 pipeline；MOSS 不减 | `SRC` `krea2/krea2.py:455`、`moss_image/moss_image.py:403` |
| 采样器行为异常 | SDXL 的 `sample.sampler` 必须与 `train.noise_scheduler` 一致；Krea2/MOSS **不读** `sample.sampler`，改它没用 | `SRC` 示例 yaml 注释、「must match train.noise_scheduler」；`krea2.py:411-467`、`moss_image.py:371-411` |
| 边缘被切、构图总是同一种比例 | 分辨率桶：`resolution` 是**面积上限**，小图不会被放大，只按 `bucket_tolerance`（默认 64）对齐；SDXL/Krea2/MOSS 的桶对齐都是 16 的倍数 | `SRC` `toolkit/buckets.py:17-48`、`dataloader_mixins.py:260-350`、`stable_diffusion_model.py:364-372` |
| 开了 TE 训练但毫无变化 | Krea2/MOSS 的 TE 是 Qwen 系，ai-toolkit 的 TE LoRA 只认 `CLIPAttention/CLIPMLP` → **建出 0 个 TE LoRA，不报错** | `SRC` `toolkit/lora_special.py:284,655-676` |

**只改一个**：从这张表里挑一项，改完重跑同一组采样，不要顺手改 lr。

## 3. 症状主表

每条四段：**看到什么 → 大概是什么 → 先动哪个 → 再动哪个**，末尾给**停止条件**和**per-model 覆盖**（只在三款模型动作不同时才写）。

### 3.1 过拟合：衣服 / 背景被绑定

**看到什么**
- 换了提示词和场景，人物还是那套衣服、同一个背景，或者背景里固定的家具/纹理反复出现；
- 训练集里出现频率最高的标签，在出图里「不需要也在」；
- 泛化提示词（「在厨房」「穿西装」）压不过训练集语境。

**大概是什么**
- 步数超过数据量能承受的点。小数据集上这非常常见：HF 官方博客里 27 张风格图用 2500 步**明显过拟合**，1000 步（batch 1–2）才平衡（`SRC` HF 博客 `sdxl_lora_advanced_script.md`）。
- 并非「rank 太大」——rank 大通常先表现为细节变僵、皮肤发蜡，不是场景被绑定。
- 数据构成单一（同一套衣服出现在几乎每张图）会把服装学成角色的一部分。

**先动哪个**
1. **先降步数**，不动其他：2500 → 1500 → 1000，取中间存盘比较（`SRC` 同上）。
2. 停在与数据量匹配的档：人脸小集 HF 用的是 **120 × 张数**（6 张 → 720 步），可直接当起点（`SRC` HF 博客）。
3. 步数降了还绑，再降 lr：1e-4 → 5e-5（`COMMUNITY` 通用做法，未实测）。

**再动哪个**
- 数据侧：把「每张都出现」的服装/背景写进 caption（让它变成可被提示词控制的条件，而不是角色的一部分）。
- 最后才动 rank：32 → 16，且只在你已经确认步数和 lr 都调过之后。

**停止条件**
在「换背景、换服装」的提示词下，中间存盘 **不再固定复现**那套衣服/那个背景，而角色本身仍可辨认 → 停。再降步数会开始丢特征（脸变模糊、发型跑掉），那就是降过头了。

**per-model 覆盖**
- SDXL：触发词放最前 + 77 token 内，别让「每张都一样」的标签占掉额度（`SRC` `train_tools.py:402-422`）。
- Krea2 / MOSS：prose 写「变化的」、身份特征不进 caption；同一套衣服不要每张都描述（`SRC` `docs/models/krea2.md` ④）。

### 3.2 欠拟合：触发词不生效

**看到什么**
- 提示词里写了触发词，但角色/概念不出现，或只有一点点像；
- 需要把触发词权重拉很高才勉强出，且一出就崩；
- 所有中间存盘都一样「不像」。

**大概是什么**
- 最常见**不是训练不足，而是触发词根本没进 caption**（§2 第一行）：被 77 token 截断、`trigger_word` 写错层、或 caption 里压根没写。
- 其次才是步数/lr 不够。
- 还有一类：训练集里同一概念有多个叫法，模型学成了「平均」。

**先动哪个**
1. **先验证触发词进了训练数据**：抽 5 张图的 `.txt`，确认触发词在，且总长度没超上限（`SRC` `train_tools.py:402-422`）。
2. 再看中间存盘：如果 1500 步仍完全不像，**加步数**（2500 → 3500，`COMMUNITY` 区间）。
3. lr 1e-4 → 1.5e-4 只在「步数加了仍不动」时才试，且一次只加这一项。

**再动哪个**
- 检查 caption 是否在描述身份特征（Krea2/MOSS 的规则是**不写**身份，靠触发词绑定；写了反而分散）。
- 检查数据集里该概念是否只有 3–5 张（样本太少），补图比调参有效。

**停止条件**
换新种子、新构图，触发词都能稳定带出该角色/概念（连续 4 张里至少 3 张可辨认）→ 停。继续加步数会开始绑定背景（转 §3.1）。

**per-model 覆盖**
- SDXL：先查 **77 token 截断**（最容易踩）。
- Krea2：先查 system 指令模板下的写法（`color/shape/size/texture/quantity/text/spatial relationships` 描述体系），以及 512 token 上限（`SRC` `krea2/src/text_encoder.py:28-33,45`）。
- MOSS：先查段名/结构是否符合官方 recaptioner 口径（4096 token，但长 caption 会让 attention 变贵，`SRC` `moss_image.py:70`）。

### 3.3 脸漂（同一角色，换角度/表情就认不出）

**看到什么**
- 正面像，侧脸/低头/大笑就变成另一个人；
- 换构图（半身→全身）五官比例漂移；
- 同一个 seed 下，不同采样步数出的人不一样。

**大概是什么**
- 数据里特写占比过高、缺少「同一个人不同角度」的样本 → 模型只学了正面模板。
- 桶对齐把脸裁掉了一部分（构图问题，不是训练问题）。
- 采样器/步数不合适，尤其在蒸馏模型上（Krea2 Turbo）。

**先动哪个**
1. 先按 §2 排桶与采样，确认不是裁切或采样参数造成的。
2. 加数据：补同一人的侧脸/半身/全身，保持身份一致（`SRC` HF 博客「要特写也要全身，避免人物太远的照片」）。
3. 再看 `content_or_style`：character 类保持 `balanced`，别为了细节调到 `style`（`SRC` `toolkit/config_modules.py:384-385`）。

**再动哪个**
- Krea2：采样器换 `Euler + simple`（`COMMUNITY`，单人报告：`res_2s` 漂脸）。
- SDXL：开 TE 训练可提升身份一致性，但要按 kohya 的 `--text_encoder_lr1/2=1e-5` 量级，别用 UNet 的 1e-4（`SRC` kohya `docs/sdxl_train_network.md`）。

**停止条件**
同一 seed 下 3 个不同角度/表情都能辨认是同一人，且 CFG ±1 不明显变形 → 停。

**per-model 覆盖**
- Krea2：**Turbo 是蒸馏模型**，采样器与步数对脸影响比 SDXL 大；先用 Raw 验收，再回 Turbo 看效果（`SRC` `docs/models/krea2.md` ③）。
- MOSS：`uncond_skip_layers`（SLG）关掉会让细节更「真」但整体塌，脸漂时先确认 SLG 设置没动过（`SRC` MOSS `USERGUIDE`）。

> 本条整体证据弱：脸漂的多数说法来自社区（`COMMUNITY`），Krea2 `res_2s` 那条是**单人报告**，未复现。

### 3.4 概念泄漏到无关图

**看到什么**
- 完全不提这个角色/概念的提示词，出图里也冒出它（发色、服装、标志物）；
- 同时加载别的 LoRA 时互相污染；
- 降低 network multiplier 也没用。

**大概是什么**
- 训练把概念绑到了「全局风格」而不是触发词上：caption 里没写它、或触发词没进 caption，模型只能靠画面本身学。
- 步数过头 + 数据单一，让概念渗进基座先验。
- `diff_output_preservation`（DOP）会**把数据集加载两遍**，显存和步时都翻倍，`train_text_encoder` 同开还会直接抛错（`SRC` `SDTrainer.py:95-102`）。

**先动哪个**
1. 先确认触发词与 caption：泄漏通常是「没写清楚」而不是「学太多」。
2. 降步数（回到过拟合前的那档）。
3. 确认 DOP 的开关：它要触发词，且会翻倍加载（`SRC` 同上）。

**再动哪个**
- 推理侧降 `network_multiplier`（0.8 → 0.6）只能缓解，不能修根因。
- 数据侧：把这个概念在「不该出现」的图里也描述清楚，让它可被条件控制。

**停止条件**
写无关题材（连续 4 张、不含触发词）不再出现该角色/标志物 → 停。

**per-model 覆盖**
- Krea2：有单次报告称泄漏后「换早期 ckpt / 降 multiplier 都无效」（`COMMUNITY`，未复现）——这种情况下直接回炉重训比继续调参快。

### 3.5 全景好、特写崩

> **本条证据最弱，属排除式排查，不是定论。** 先按下面顺序排除，别把它当「训练问题」直接调参。

**看到什么**
- 全身/远景能认出角色，一裁到脸或小物件就糊、变形、细节错；
- 同一张图放大后局部崩，但缩略图看着还行。

**大概是什么**（按可能性排）
1. 桶与分辨率：训练图被裁/缩放后，脸的像素本来就不够；`resolution` 是面积上限，小图不会被放大（`SRC` `buckets.py:17-48`）。
2. caption 长度：MOSS 上一手实测显示 caption 越长步时越高（1.9k token 时 attention FLOPs +53%），长 caption 会挤掉图像 token 的有效学习（`SRC` `anima_lora` `project/moss_lora/plan.md`，一手实测）。
3. 采样：步数/CFG/SLG 不匹配（§2）。

**先动哪个**
1. 查桶：出图尺寸与训练桶是否一致；训练集里脸的像素够不够。
2. 查 caption 长度：把长 caption 截到「必要信息」再训一版对比。
3. 再看采样参数。

**再动哪个**
- 补特写图（同一个人、同一套服装，脸部占画面比例更大）。
- 最后再考虑提高分辨率训练（显存代价大）。

**停止条件**
1024 桶的特写与 512 桶的全景都能看清关键特征，且换采样器不明显变差 → 停。

**per-model 覆盖**
- MOSS：特写崩与长 caption 强相关，优先查 caption 长度（`SRC` 上述一手实测）。

## 4. 附带症状（简版）

- **图里文字永远拼不对**：SDXL 的 CLIP 文本编码本身不擅长长文本；这不该当训练验收指标，写进「已知限制」（`SRC` `docs/models/sdxl.md` ⑤）。MOSS 是唯一以文字渲染为目标的，验收要单独出文字样图。
- **道具被焊进角色**：训练集里每张都有同一个道具 → 道具被学成角色的一部分。先按 §3.1 降步数，再在 caption 里把道具写成可替换的（`COMMUNITY`）。
- **手部崩坏**：小数据集 + 手部像素不足；补手部清晰图比调参有效（`COMMUNITY`）。
- **风格渗透**：训练集本身的画风/滤镜被学进去，换提示词也带着。风格类 LoRA 这是预期行为；角色类出现说明数据风格太单一，补不同光照/画风的图（`COMMUNITY`）。

## 5. 记录模板

纯文本，一行一次实验，直接抄：

```
症状：过拟合（衣服被绑定）
改前值：steps 2500 / lr 1e-4 / rank 32
只改的那项：steps → 1500
结果：1000 步存盘，换背景提示词不再复现原服装；角色仍可辨认（seed 42，512 桶，25 步，CFG 6）
下一步：保持 1500，补 3 张侧脸
```

五个字段：**症状 / 改前值 / 只改的那项 / 结果（含步数与种子）/ 下一步**。不要一次记两条。

## 6. 第二批数据补什么（8 行内）

| 症状 | 补哪类图 |
|---|---|
| 过拟合、衣服被绑定 | 同一角色、**换服装换背景**的图 |
| 脸漂 | 同一个人 **侧脸/半身/全身** 各若干 |
| 特写崩 | 同一套造型的**脸部占比更大**的图 |
| 概念泄漏 | 该概念**不该出现**的对照场景图 |
| 欠拟合 | 该概念**不同角度/光照**的补充图（先确认 caption 没截断） |

采集方法不在本手册范围。
